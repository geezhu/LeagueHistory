# 诊断日志与报告

用户遇到问题时，在「设置 → 功能辅助 → 关于与交流」点「导出诊断报告…」，把生成的 zip 发给开发者。报告只保存在本机，不会自动上传。同一位置的「版本」一行显示版本号和构建 commit，可一键复制。

## 报告内容

zip 根目录的 `report.json`：

| 字段 | 内容 |
|---|---|
| `build` | 版本（version.txt）、完整 commit、构建时是否有未提交改动、构建时间 |
| `environment` | Windows 与 .NET 版本、是否管理员、语言、时区、屏幕、本次运行时长 |
| `client` | 客户端在线时的游戏版本、大区、语言；读不到时写明原因 |
| `processes` | 客户端、游戏、Riot 客户端、WeGame、Game Bar 组件的进程数量（只记进程名） |
| `app` | 客户端是否连接、是否在对局、当前游戏阶段、Game Bar 组件状态、语音模型、安装目录识别结果 |
| `config` | 配置文件，去掉自定义发送内容（只留字数）和麦克风设备 ID |
| `files` | 收录的日志文件及大小、修改时间 |

其余文件为最近 7 天的日志：

- `logs/`：`%LOCALAPPDATA%\League\Logs` 下的程序日志
  - `app-日期.log`：应用日志，见下文
  - `tier-chat.log`：快捷发送的阶段和失败原因
  - `room-players.log`：房间卡片加载
  - `assistant.log`：选人助手错误
  - `last-crash.json`：上次异常退出的标记（启动时读取后删除，所以通常不在报告里）
- `gamebar/`：Game Bar 组件的错误日志、活动日志（含 `.previous.txt` 轮转文件）和心跳 `widget-status.json`
- `shutdown/`：到点关机任务日志

## 应用日志

每行格式：`时间 pid=进程号 [级别] [类别] 内容`。每个进程第一次写入时先写一行 `session`，带版本、commit、系统和是否管理员。

| 类别 | 记录什么 |
|---|---|
| `App` | 启动、导出报告、主窗口初始化失败 |
| `Connection` | 客户端进程查找失败原因（含原生读取和 WMI 错误码）、接口测试结果、断线 |
| `Sgp` | 战绩服务初始化卡在哪一步、服务地址、查询连续失败的原因和恢复 |
| `Update` | 检查更新结果、下载重试、更新开始和失败 |
| `Game` | 游戏阶段变化、选人和对局的队列 |
| `Automation` | 自动预选（做了什么或为什么没做）、板凳席换英雄、自动换皮肤、自动接受、结算后操作 |
| `Data` | 战绩、召唤师、英雄、图片等读取和解析失败 |
| `Ui` | 界面失败、界面卡顿（超过 2 秒无响应及恢复） |
| `Crash` | 未处理异常（含完整调用栈）、未观察的后台任务异常 |

分析时先按 `[Game]` 的阶段变化找到出问题的时间段，再看同一时段的其他类别。

## 去敏

写日志和导出报告时都经过 `DiagnosticRedactor`：用户目录换成 `%USERPROFILE%`；删掉客户端令牌、URL 凭据、授权头和 JWT；PUUID 和 UUID 形式的 ID 换成 `id:` 加 8 位哈希。同一进程内相同的 ID 得到相同的哈希，可以对照，但看不出原值。

## 保留

日志目录启动时在后台清理：超过 7 天的删除，剩下的总大小超过 20 MB 时从最旧的删起。单个日志超过上限（应用日志 4 MB，其他 256–512 KB）改名为 `.previous` 后继续写。

## 写新日志

- 用 `AppLog.Shared`，选对类别。`Info` 记结果，`Warn` 记可恢复的失败（附上异常对象），`Error` 记功能失败。
- 每秒或每几秒都会执行的检查用 `State(类别, 键, 内容)`，只在内容变化时写一行；需要每局重新记录时用 `ResetStates`。
- 相同的警告 60 秒内只写一次，之后写入时注明期间重复的次数，不用自己做节流。
- 不写玩家名、Riot ID、聊天正文、令牌和请求地址里的玩家 ID。记阶段、状态码、异常类型和原因。
- `Debug.WriteLine` 在 Release 版会被去掉，只适合调试时临时看的过程信息。
