# Game Bar 对局速览（验证版）

显示组件使用微软 Xbox Game Bar SDK，主程序保留 WinForms。通过 Win＋G 打开和管理面板；主程序与组件均不注册速览快捷键，也不调整 LOL 的显示模式。全屏覆盖是否可用需要在实际游戏中确认，注册和编译成功不能代替该验证。

## 使用

1. 构建并安装下述开发组件。
2. 启动新版 League.exe，在「设置 → 功能辅助 → 对局速览」选择 **Game Bar（全屏验证版）**。
3. 按 **Win＋G**，从小组件列表打开 **League 对局速览**。需要保留在游戏上方时，点击组件右上角图钉。
4. 保持 League 主程序运行，进入加载 / 游戏阶段后同步十名玩家的英雄、梯队、胜率、选用率和已缓存战绩。通过 Win＋G 查看或关闭组件；关闭后可从小组件列表重新打开。

未固定时，退出 Win＋G 会隐藏组件；固定时，退出 Win＋G 后仍可显示在游戏上方。内容区会显示当前固定状态。点 × 可关闭组件，之后在 Win＋G 中重新打开。

点击英雄卡片可在同一组件内查看详情，顶部十个头像可切换双方英雄，「返回」回到速览。技能支持悬浮说明和点击阅读；出装首先展示该英雄的单件推荐装备网格，包含名称、图标、胜率和使用率，悬浮查看介绍与样本量，下方保留核心组合、后续装备及两组召唤师技能推荐。单件统计来自 OP.GG 的 `last_items` 或 arammeta 的 `singleItems`，不把组合胜率当作单件胜率；来源缺项时显示暂无数据。普通模式显示符文，海克斯大乱斗显示三种品质的强化推荐。强化是来源推荐，不表示玩家实际已选。

详情需要同时更新主程序和组件。只在选中英雄后加载；arammeta 复用已有落盘缓存和设置中的过期时间，OP.GG 使用 15 分钟内存缓存，图片复用客户端资源缓存。切换或返回会取消旧选择，失败可重试。Game Bar 鼠标穿透开启时需通过 Win＋G 操作按钮。

底部可「发送我方 Tier」「发送敌方 Tier」，进入任一英雄详情后可「发送此英雄」。消息带来源、模式、梯队、胜率及选用率，直接复用当前速览的缓存；海克斯大乱斗注明调整后胜率和样本选取率，峡谷参考分路也会标注。发送敌方是分享敌方英雄的数据，不切换为所有人聊天频道。

需以管理员身份运行 League.exe，并已进入游戏。点击后在 20 秒内按 Win＋G 返回游戏，保持聊天输入框关闭，主程序才会使用已有游戏输入通道发送；组件底部显示结果，可在等待时取消。加载界面不能发送，统计未就绪会提示重试。无需固定组件，也不会自动切换窗口或新增快捷键。桌面预览禁用发送。

桌面速览仍可在设置中选择。独占全屏时桌面版本暂停显示，避免把游戏切到桌面。「测试桌面显示」仅检查桌面窗口。

应用设置统一保存到 `%LOCALAPPDATA%/LeagueHistory/LeagueConfig.json`。首次启动会导入 exe 同目录的旧配置，其次检查旧启动目录；原文件保留。之后更换 exe 目录仍读取同一份设置，不会重置 Game Bar 选择。首次使用新版并移到新目录时，需一并带上旧 `LeagueConfig.json` 完成首次导入。

## 开发构建

需要 Windows 10 2004+、Xbox Game Bar、VS 2022 C++ 工具和 Windows SDK（包含 C++/WinRT）。不需要安装 UWP XAML 编译工具：界面使用原生 XAML 控件构造。

```powershell
./GameBar/Build.ps1
./GameBar/Install-Development.ps1
```

SDK 固定为 Microsoft.Gaming.XboxGameBar 7.3.2607010，首次构建从 NuGet 下载；原生 DLL、元数据和 SDK 自带资源随组件打包。注册项从同版本元数据生成，防止 SDK 接口变化后使用过期 GUID。应用图标复用项目 favicon。

安装脚本仅在电脑原本已启用开发模式时注册当前用户的组件，不自动开启开发模式、不导入证书。构建产物在 `bin/GameBar`，注册后必须保留 `Package` 目录。生成的 MSIX 尚未签名，不是普通用户直接双击安装的发行包；正式分发需要签名和相应分发流程。

更新构建需提高清单版本号，否则 Windows 可能继续指向旧安装目录。脚本会核对实际安装位置，并在更新后退出 Game Bar 的界面进程，使下次打开时重新加载组件，避免留下空白旧窗口；不会结束游戏或 League 主程序。录制服务运行时跳过重启，也可用 `-KeepGameBarRunning` 跳过，然后自行重开 Game Bar。

卸载开发组件：

```powershell
Get-AppxPackage -Name LeagueHistory.GameBar | Remove-AppxPackage
```

## 数据与生命周期

玩家卡片与英雄详情显示该玩家使用当前英雄的成就等级、点数；悬浮可查看精确点数、最近使用时间（接口提供时）与缓存更新时间。成就属于玩家长期积累，独立于英雄的梯队、胜率和选用率。

助手、个人资料与速览共用客户端成就查询和本地缓存，默认有效期 30 分钟，可在「设置 → 数据缓存 → 玩家英雄成就」修改。缓存位于 `%LOCALAPPDATA%/League/Cache/mastery`，按平台、当前账号及目标玩家分隔，文件名使用散列；仅保存成就字段，不保存令牌。过期时先显示旧值、后台更新；失败退避一分钟，身份隐藏、权限拒绝与无成就记录分别显示。自己的对局结束后失效。Game Bar 只接收展示文本，不直接访问客户端或获取账户标识。

- 只传本机 JSON，位置为组件的 `%LOCALAPPDATA%/Packages/LeagueHistory.GameBar_*/LocalState/snapshot.json`；不传 LCU 令牌、账户标识或接口地址。
- 详情使用独立 `detail-request.json` / `detail.json`，只传当前会话、卡片位置、英雄编号和请求标识。主程序核对当前十人名单，组件核对回包的会话与请求；旧对局、旧选择和空缺位置不会触发或覆盖详情。返回速览发送取消请求。
- 聊天使用独立 `chat-request.json` / `chat-status.json`，仅接受我方、敌方或当前卡片的显式请求，不接受任意消息文本。主程序按会话和请求编号去重，核对名单、游戏阶段、超时与管理员权限。组件通过 [GameBarDisplayMode](https://learn.microsoft.com/en-us/gaming/game-bar/api/enum-xgb-displaymode) 报告已退出 Win＋G，主程序还须确认游戏稳定处于前台且修饰键均已松开；对局变化、取消或重新打开 Game Bar 都会停止待发送输入。输入完成不代表服务器已确认收到。
- 详情文件仅在加载进展变化时更新，完成后组件停止读取；不会随三秒一次的阵容刷新重复发布推荐和图标。
- 主程序复用现有统计和图片缓存。48px PNG 每个英雄只编码一次；写入队列容量为一，合并快速更新，通过临时文件替换发布完整快照。
- 默认约每 3 秒更新数据，组件以 500ms 间隔检查本机快照，单次读取互斥。超过 15 秒未有有效数据即清空旧阵容。没有第二套远程统计请求。
- 显示命令与数据版本分开：刷新胜率、头像不恢复用户手动收起的组件。程序实例 / 对局切换会重置显示命令。
- 对局速览不订阅原始键盘、全局快捷键或 SDK 快捷键事件，旧配置中的速览按键字段会被忽略。聊天快捷键不受影响。
- 新组件忽略旧主程序的按键切换命令。快照仅保留空的 `shortcut` 与 `shortcutOwner=main` 兼容标记，阻止旧组件重新启用 SDK 按键监听；不再发布按键计数或时间。
- `widget-status.json` 记录连接、固定、可见状态与读取错误；`component-error.txt` 记录组件启动异常，`component-diagnostics.txt` 记录激活与固定 / 可见状态变化。
- 回执同时记录实际绘制的玩家数、界面尺寸和读取错误。主程序写出了快照但没有收到组件回执时，设置会明确显示“组件未连接”。
- 大厅、选人和结算阶段继续发送连接回执，分别显示等待对局、选人中、本局结束。主程序数据超过 15 秒未更新时才清空旧阵容并提示数据中断，恢复后自动重连；短暂的单次读取失败不会误报断开。
- 从开始菜单打开组件时，显示使用同一套渲染代码的桌面预览。头像独立解码，不阻塞其他玩家或连接回执。

## 验证

英雄识别兼容 `game_character_displayname_<英雄>` 和 `Character_<英雄>_Name`（例如萨勒芬妮的 `Character_Seraphine_Name`），并可用客户端资源中的完整名称匹配。合并名单时，若实时名称暂不能识别，保留同阵营、身份唯一匹配的 LCU 英雄编号；不按位置或相同英雄猜账号。未识别的游戏名称标识会在 `room-players.log` 的 `overlay-heroes` 行记录，状态变化时才写入，不包含玩家名称和账号。

熟练度发送：选人助手的成就行可发送自己当前英雄的等级与点数；Game Bar 底部的“发送熟练度”菜单可选择我方、敌方或当前英雄。Game Bar 沿用游戏聊天发送流程，主程序需要管理员权限，点击后须在 20 秒内按 Win＋G 返回游戏并保持聊天框关闭。过期缓存与未公开身份会标注，全部数据不可用时拒绝发送。组件只提交发送类型和当前对局的英雄位置，由主程序生成文本；没有新增快捷键。

LCU 因隐藏玩家只返回部分名单时，先查询已公开召唤师的完整 Riot ID，再与 Live Client 十人名单合并，保留其 PUUID。隐藏位置不按英雄猜账号；无法匹配的公开身份显示“成就待确认”。身份资料按对局与连接缓存，失败退避一分钟；`room-players.log` 的 `overlay-identities` 行记录名单和已确认 / 隐藏人数，不写账号或名称。

连续死亡：对局页面和 Game Bar 卡片 / 详情显示“连死 N · 最高 M”。死亡加一，击杀清零，助攻不清零；环境死亡也计入。复用现有轮询，从 2999 的本局事件历史重建并去重，不跨对局累计、不另行落盘。死亡 / 击杀总数用于检查历史完整性；`*` 表示仅统计已取得的事件，悬浮可看规则。缺少事件、隐藏 / 重名身份或比分尚未同步时显示未知，避免显示假的零。

Game Bar 底部“发送连死”菜单支持我方、敌方及当前选中英雄，发送格式为 `【海克斯大乱斗·我方】连死/本局最高：拉克丝 3/5、莫甘娜 0/2`。不完整历史标注“已记录”，无法匹配的玩家显示“未知”；全部未知或事件超过 15 秒未更新时拒绝发送。退出 Win＋G 后，主程序使用最新轮询结果生成文案，复用已有权限、对局核对、取消与返回游戏检查，不自动发送、不新增快捷键。

```powershell
dotnet run --project Tests/StatisticsChecks/StatisticsChecks.csproj -c Release -- --loading-overlay-checks
```

自动检查覆盖本机快照原子替换、最新数据优先、双队分组、空缺位置、头像、统计字段、关闭时清空、旧按键配置忽略和显示后端切换。仍需人工检查：Win＋G 组件加载、固定、全屏加载画面中的显示与关闭后重新打开。

原生界面检查：运行 `GameBar/Verify-Preview.ps1`，用当前主程序缓存绘制预览并保存组件自己的 `LocalState/preview-verification.png`。该检查通过应用激活接口传入专用参数，不发送任何游戏输入；正常启动不会保存预览图。检查预览与 Game Bar 使用不同回执文件，避免把桌面预览误判为游戏内连接成功。

详情布局检查：测试项目的 `--overlay-detail-fixture <输出目录> <已有 Assets 目录>` 导出明确标注的样例，复制其中两个 `detail-preview-*.json` 到组件 `LocalState` 后运行 `GameBar/Verify-Preview.ps1 -DetailTab skills`（或 `builds` / `augments`）。截图使用同一渲染代码，样例文件独立于真实快照与请求；默认检查 820×560，也可在样例快照中设置 `width` / `height` 检查最小 640×500。它不代替实际全屏交互验证。
