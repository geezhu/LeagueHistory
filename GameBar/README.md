# Game Bar 对局速览（验证版）

显示组件使用微软 Xbox Game Bar SDK，主程序保留 WinForms。通过 Win＋G 打开和管理面板；主程序与组件均不注册速览快捷键，也不调整 LOL 的显示模式。全屏覆盖是否可用需要在实际游戏中确认，注册和编译成功不能代替该验证。

## 使用

1. 发布包用户：在「设置 → 对局速览」选择 Game Bar 后，点「Game Bar 组件 → 安装组件」。发布包里的组件安装包不签名；安装时主程序在本机生成一张自签名证书（`CN=LeagueHistory`，私钥不可导出，只存在当前用户的证书存储），用它给安装包的临时副本签名后安装。首次安装会弹出一次管理员授权，把这张本机证书加入“受信任的人”；组件本身只为当前用户安装，不需要开启开发者模式。开发时也可以用下述开发组件。
2. 启动新版 League.exe，在「设置 → 功能辅助 → 对局速览」选择 **Game Bar（支持全屏）**。
3. 按 **Win＋G**，从小组件列表打开 **League 对局速览**。需要保留在游戏上方时，点击组件右上角图钉。
4. 保持 League 主程序运行，进入加载 / 游戏阶段后同步十名玩家的英雄、梯队、胜率、选用率和已缓存战绩。通过 Win＋G 查看或关闭组件；关闭后可从小组件列表重新打开。

未固定时，退出 Win＋G 会隐藏组件；固定时，退出 Win＋G 后仍可显示在游戏上方。内容区会显示当前固定状态。点 × 可关闭组件，之后在 Win＋G 中重新打开。

点击英雄卡片可在同一组件内查看详情，顶部十个头像可切换双方英雄，「返回」回到速览。技能支持悬浮说明和点击阅读；出装首先展示该英雄的单件推荐装备网格，包含名称、图标、胜率和使用率，悬浮查看介绍与样本量，下方保留核心组合、后续装备及两组召唤师技能推荐。单件统计来自 OP.GG 的 `last_items` 或 arammeta 的 `singleItems`，不把组合胜率当作单件胜率；来源缺项时显示暂无数据。普通模式显示符文，海克斯大乱斗显示三种品质的强化推荐；推荐页顶部可搜索名称、效果或拼音首字母（如「坦克引擎」输入 tkyq，首字母由主程序按 GB2312 一级汉字推算，见 `ChineseInitials`），有搜索词时不分品质列出全部匹配，名称匹配在前，并标出所属品质。强化是来源推荐，不表示玩家实际已选。

详情需要同时更新主程序和组件。只在选中英雄后加载；arammeta 复用已有落盘缓存和设置中的过期时间，OP.GG 使用 15 分钟内存缓存，图片复用客户端资源缓存。切换或返回会取消旧选择，失败可重试。Game Bar 鼠标穿透开启时需通过 Win＋G 操作按钮。

底部可「发送我方 Tier」「发送敌方 Tier」，进入任一英雄详情后可「发送此英雄」。消息带来源、模式、梯队、胜率及选用率，直接复用当前速览的缓存；海克斯大乱斗注明调整后胜率和样本选取率，峡谷参考分路也会标注。发送敌方是分享敌方英雄的数据，不切换为所有人聊天频道。

需以管理员身份运行 League.exe，并已进入游戏。点击后在 20 秒内按 Win＋G 返回游戏，保持聊天输入框关闭，主程序才会使用已有游戏输入通道发送；组件底部显示结果，可在等待时取消。加载界面不能发送，统计未就绪会提示重试。无需固定组件，也不会自动切换窗口或新增快捷键。桌面预览禁用发送。

底部「语音输入」打开中文聊天编辑区。麦克风与选人助手共用，可到「设置 → 消息发送 → 本机语音识别」选择或刷新设备，默认跟随 Windows 默认输入。WASAPI 共享采集转换为 16k 单声道，麦克风与模型并行准备，设备返回首批数据后才提示“可以说话了”。准备和识别只在按钮显示状态，移除重复引擎说明及每秒提示，结果直接留在编辑区；保留轻声输入并进行有限增益；日志只记录数据包数、采样数和峰值，不记录音频或识别文字。点击「开始录音」，说完后点「停止录音」，检查或修改文字，再点「确认发送」；也可直接输入文字。确认后在 20 秒内按 Win＋G 返回游戏，并保持聊天框关闭，沿用已有管理员输入通道发送到当前聊天频道。最多 180 个 UTF-16 字符，只发送一条普通聊天消息，不支持换行或斜杠命令；识别完成不会自动发送。正在等待时可用「取消发送」，文字修改后必须重新确认。

录音由主程序复用选人助手的 SenseVoice 中文模型，使用默认麦克风，需要桌面应用麦克风权限。说完后停止录音，再转换文字，识别期间显示「正在识别」；尚未得到最终文字时不能确认发送。无需联网、Windows 中文语音组件或开启在线语音识别，组件不直接申请麦克风权限。模型缺失或损坏时，到「设置 → 消息发送 → 本机语音识别」下载或修复（约 228 MiB）；自带模型的发布包直接使用。模型来源固定到版本并校验 SHA-256，模型及许可保存在 `%LOCALAPPDATA%/League/VoiceModels/SenseVoice-2024-07-17-int8`，或发布包的 `VoiceModels/SenseVoice`。识别使用 2 个 CPU 线程，同时最多处理一段录音，不占用游戏 GPU，识别结束后释放模型；没有可比较的置信度分数，不显示虚构的准确率。

麦克风只在用户点击录音后启用，与模型加载并行；录音先暂存在内存，停止后等模型就绪再识别，最长 20 秒；退出 Win＋G 或隐藏组件时停止录音并转换已有内容，关闭编辑区、切换对局、断开连接或应用挂起时取消录音。录音请求以 500ms 心跳续期，主程序每 400ms 检查；组件关闭或断开后超过 3 秒没有续期即释放麦克风。总会话最多约 55 秒，包含加载、录音和识别；已取消的识别结果不会回填。PCM 音频仅保留在内存，结束后清理。识别异步运行，不使用常驻监听或新快捷键。

不保存音频，不把草稿写入缓存或日志。组件与主程序通过独立的 `voice-request.json` / `voice-status.json` 临时同步录音状态和识别文字；组件收到文字后回执，主程序删除已收到的临时内容，关闭、超时、换局或主程序重启时也清理。录音协议不接受聊天内容或发送指令，不依赖玩家身份和英雄统计。只有用户确认后才生成 `chat-request.json`；处理结束、取消或组件超时后删除该请求，发送状态与诊断日志不包含文字。原有统计请求不接受文字；主程序核对确认标记、长度、单行内容、会话、时间与请求编号，确认后替换文字会取消发送。输入完成仍不代表游戏服务器确认收到消息。

桌面速览仍可在设置中选择。独占全屏时桌面版本暂停显示，避免把游戏切到桌面。「测试桌面显示」仅检查桌面窗口。

应用设置统一保存到 `%LOCALAPPDATA%/LeagueHistory/LeagueConfig.json`。首次启动会导入 exe 同目录的旧配置，其次检查旧启动目录；原文件保留。之后更换 exe 目录仍读取同一份设置，不会重置 Game Bar 选择。首次使用新版并移到新目录时，需一并带上旧 `LeagueConfig.json` 完成首次导入。

## 开发构建

需要 Windows 10 2004+、Xbox Game Bar、VS 2022 C++ 工具和 Windows SDK（包含 C++/WinRT）。不需要安装 UWP XAML 编译工具：界面使用原生 XAML 控件构造。

```powershell
./GameBar/Build.ps1
./GameBar/Install-Development.ps1
```

SDK 固定为 Microsoft.Gaming.XboxGameBar 7.3.2607010，首次构建从 NuGet 下载；原生 DLL、元数据和 SDK 自带资源随组件打包。注册项从同版本元数据生成，防止 SDK 接口变化后使用过期 GUID。应用图标复用项目 favicon。

安装脚本仅在电脑原本已启用开发模式时注册当前用户的组件，不自动开启开发模式、不导入证书。构建产物在 `bin/GameBar`，注册后必须保留 `Package` 目录。不带证书参数时生成的 MSIX 未签名，只用于开发。

## 发布

```powershell
./Scripts/Publish-Release.ps1 -Version 1.1.0
```

发布包在 `bin/Publish/<版本>`，另有同样内容的一键安装程序 `League-<版本>-setup.exe`（`Scripts/Installer/LeagueHistory.iss`，默认勾选安装组件，见主 README）：League.exe 自带 .NET 运行时；`GameBar/` 下是未签名的组件安装包，由设置页在用户电脑上用本机证书签名后安装，项目不持有任何签名私钥，任何人都能打发布包；不附带语音模型，用户在设置中下载（先尝试 hf-mirror.com，再 huggingface.co，支持断点续传，校验 SHA-256）。签名使用 Windows 自带的 `mssign32.dll`，用户无需安装 SDK。因为签名在本机完成，它不证明安装包的来源；请在发布页提供压缩包的 SHA256。已用开发脚本注册同版本组件的电脑，需先卸载开发组件再安装发布版。

更新构建需提高清单版本号，否则 Windows 可能继续指向旧安装目录。脚本会核对实际安装位置，并在更新后退出 Game Bar 的界面进程，使下次打开时重新加载组件，避免留下空白旧窗口；不会结束游戏或 League 主程序。录制服务运行时跳过重启，也可用 `-KeepGameBarRunning` 跳过，然后自行重开 Game Bar。

卸载开发组件：

```powershell
Get-AppxPackage -Name LeagueHistory.GameBar | Remove-AppxPackage
```

## 数据与生命周期

玩家卡片与英雄详情显示该玩家使用当前英雄的成就等级、点数；悬浮可查看精确点数、最近使用时间（接口提供时）与缓存更新时间。成就属于玩家长期积累，独立于英雄的梯队、胜率和选用率。

助手、个人资料与速览共用客户端成就查询和本地缓存，默认有效期 30 分钟，可在「设置 → 数据缓存 → 玩家英雄成就」修改。缓存位于 `%LOCALAPPDATA%/League/Cache/mastery`，按平台、当前账号及目标玩家分隔，文件名使用散列；仅保存成就字段，不保存令牌。过期时先显示旧值、后台更新；失败退避一分钟，身份隐藏、权限拒绝与无成就记录分别显示。自己的对局结束后失效。Game Bar 只接收展示文本，不直接访问客户端或获取账户标识。

- 只传本机 JSON，位置为组件的 `%LOCALAPPDATA%/Packages/LeagueHistory.GameBar_*/LocalState/snapshot.json`；不传 LCU 令牌、账户标识或接口地址。
- 详情使用独立 `detail-request.json` / `detail.json`，只传当前会话、卡片位置、英雄编号和请求标识。主程序核对当前十人名单，组件核对回包的会话与请求；旧对局、旧选择和空缺位置不会触发或覆盖详情。返回速览发送取消请求。
- 聊天使用独立 `chat-request.json` / `chat-status.json`，统计只接受我方、敌方或当前卡片的显式请求；语音文字须使用独立类型并明确确认。主程序按会话和请求编号去重，核对名单、游戏阶段、超时与管理员权限，语音消息不依赖英雄统计或玩家身份公开。组件通过 [GameBarDisplayMode](https://learn.microsoft.com/en-us/gaming/game-bar/api/enum-xgb-displaymode) 报告已退出 Win＋G，主程序还须确认游戏稳定处于前台且修饰键均已松开；对局变化、取消或重新打开 Game Bar 都会停止待发送输入。输入完成不代表服务器已确认收到。
- 详情文件仅在加载进展变化时更新，完成后组件停止读取；不会随三秒一次的阵容刷新重复发布推荐和图标。
- 主程序复用现有统计和图片缓存。48px PNG 每个英雄只编码一次；写入队列容量为一，合并快速更新，通过临时文件替换发布完整快照。
- 默认约每 3 秒更新数据，组件以 500ms 间隔检查本机快照，单次读取互斥。超过 15 秒未有有效数据即清空旧阵容。没有第二套远程统计请求。
- 显示命令与数据版本分开：刷新胜率、头像不恢复用户手动收起的组件。程序实例 / 对局切换会重置显示命令。
- 对局速览不订阅原始键盘、全局快捷键或 SDK 快捷键事件，旧配置中的速览按键字段会被忽略。聊天快捷键不受影响。
- 新组件忽略旧主程序的按键切换命令。快照仅保留空的 `shortcut` 与 `shortcutOwner=main` 兼容标记，阻止旧组件重新启用 SDK 按键监听；不再发布按键计数或时间。
- `widget-status.json` 记录连接、固定、可见状态与读取错误；`component-error.txt` 记录组件启动异常，`component-diagnostics.txt` 记录激活与固定 / 可见状态变化。
- 回执同时记录实际绘制的玩家数、界面尺寸和读取错误。主程序写出了快照但没有收到组件回执时，设置会明确显示“组件未连接”。
- 大厅、选人和结算阶段继续发送连接回执，分别显示等待对局、选人中、本局结束。主程序数据超过 15 秒未更新时才清空旧阵容并提示数据中断，恢复后自动重连；短暂的单次读取失败不会误报断开。
- 从开始菜单打开组件时，显示使用同一套渲染代码的桌面预览。头像独立解码，不阻塞其他玩家或连接回执。

## 验证

疑似组队：卡片左侧色条、玩家名称和人数徽标使用同组颜色，详情页头像边框也保留标记。人数表示当前名单里已识别的关联成员，支持 2–5 人。同组关系复用主程序已缓存的近期同队战绩，按至少两场同队关联形成分组，保持与主界面的规则一致；不新增战绩请求。悬浮与详情注明“疑似”，不代表当前实际预组队，未标记也不代表单排。仅匹配当前阵容中已确认的账号，隐藏、冲突和缺失身份不猜测；换局或历史不再支持分组时清除。

英雄识别兼容 `game_character_displayname_<英雄>` 和 `Character_<英雄>_Name`（例如萨勒芬妮的 `Character_Seraphine_Name`），并可用客户端资源中的完整名称匹配。合并名单时，若实时名称暂不能识别，保留同阵营、身份唯一匹配的 LCU 英雄编号；不按位置或相同英雄猜账号。未识别的游戏名称标识会在 `room-players.log` 的 `overlay-heroes` 行记录，状态变化时才写入，不包含玩家名称和账号。

熟练度发送：选人助手的成就行可发送自己当前英雄的等级与点数；Game Bar 底部的“发送熟练度”菜单可选择我方、敌方或当前英雄。Game Bar 沿用游戏聊天发送流程，主程序需要管理员权限，点击后须在 20 秒内按 Win＋G 返回游戏并保持聊天框关闭。过期缓存与未公开身份会标注，全部数据不可用时拒绝发送。组件只提交发送类型和当前对局的英雄位置，由主程序生成文本；没有新增快捷键。

LCU 因隐藏玩家只返回部分名单时，先查询已公开召唤师的完整 Riot ID，再与 Live Client 十人名单合并，保留其 PUUID。隐藏位置不按英雄猜账号；无法匹配的公开身份显示“成就待确认”。身份资料按对局与连接缓存，失败退避一分钟；`room-players.log` 的 `overlay-identities` 行记录名单和已确认 / 隐藏人数，不写账号或名称。

连续死亡：对局页面和 Game Bar 卡片 / 详情显示“连死 N · 最高 M”。死亡加一，击杀清零，助攻不清零；环境死亡也计入。复用现有轮询，从 2999 的本局事件历史重建并去重，不跨对局累计、不另行落盘。死亡 / 击杀总数用于检查历史完整性；`*` 表示仅统计已取得的事件，悬浮可看规则。缺少事件、隐藏 / 重名身份或比分尚未同步时显示未知，避免显示假的零。

本局战况：同样来自 2999（与 Tab 计分板和击杀播报一致）。队伍标题显示击杀、装备总价和经济差；卡片在对局中显示参团率和装备总价（KDA 看 Tab 计分板即可），阵亡时头像变暗并倒计时复活，名单上方列出对方阵亡英雄的复活秒数。装备总价按客户端物品数据的总价计算，代替 2999 不提供的他人金币。点击自己的卡片打开「本局」页：团战（12 秒内连续 3 次以上击杀）胜负、团灭和多杀，自己的有效生命、技能急速与穿透，Q / W / E / R 当前冷却（2999 的技能等级与技能急速，冷却 = 基础冷却 × 100 / (100 + 急速)；充能技能显示每层充能时间；基础冷却按客户端版本取自 CommunityDragon 的游戏数据，与减速同一次下载、同一份缓存 `cdragon-spells`，优先读法术的 `Cooldown` 值（与维基、Data Dragon 和游戏一致），旧字段 `cooldownTime` 在部分技能上是过时数值（如莫德凯撒 R 140/120/100，实际 120/110/100），只作后备；数据省略的冷却按游戏默认 10 秒；不受技能急速影响的充能（如洛 E、科加斯 E）是重施机制，不当作冷却；大乱斗、海克斯大乱斗、无限火力、快速匹配和斗魂竞技场对部分技能有专属冷却和数值（如战争之影 E 在大乱斗为 16/15/14/13/12，提莫 R 减速 20%），按当前对局模式读取（对局中取 2999 的模式，加载界面按队列推断，`GameModes`），冷却页、本局页、控制保命页的减速与覆盖率都按该模式计算；大招急速、只对部分技能生效的海克斯和命中返还未计入，回归检查 `--cooldown-checks`），以及按 arammeta 敌方物理伤害占比给出的护甲 / 魔抗优先级；出装对照选与已有装备重合最多的推荐组合并给出下一件；符文页优先用游戏内数据，海克斯大乱斗（KIWI）不提供时显示客户端当前符文页。游戏结束事件出现后，「本局」页顶部显示胜负与本局小结。

战绩：英雄详情的「战绩」页以卡片显示该玩家的胜率、近况（连胜连败）、平均 KDA、单双 / 灵活段位和近 20 场胜负色块，行为特征标签与每场信号次数（超过标签阈值时变色），以及最近对局卡片（英雄头像、胜负、KDA、时长、日期）；触发规则等说明在悬浮提示中（`DetailCards.inl`，「本局」页共用同一套卡片）。数据来自主窗口选人或加载时已查询的玩家战绩缓存（`OverlayRecordSections`），不另行请求；身份不唯一或隐藏的玩家不显示，避免张冠李戴。对局中途启动 League 时缓存里只有自己。「发送 ▾ → 战绩与特征」与 F9 / F11 格式相同（`近N场 胜率 [x%] | 发问号 … 特征 [标签]`），遵循「发送战绩时隐藏自己」和「使用英雄名称」设置；全部玩家都没有战绩时拒绝发送。「发送 ▾ → 疑似组排」按我方或敌方发送 `【疑似组排·对方】3排：[英雄…]；2排：[…]；单排：[…]；未知：[…]（按近期同队战绩推测）`，分组与名单颜色相同；有战绩但未关联的玩家列为单排，没有战绩或身份隐藏的列为未知，不当作单排。预览检查：`GameBar/Verify-Preview.ps1 -DetailTab record`，回归检查 `--overlay-record-checks`。

标记复活：在英雄详情页点「☆ 标记复活」，该英雄的名单卡片变为金色调；其阵亡、剩 5 秒复活和复活时，底部按钮上方显示提醒，剩 5 秒时单响、复活时升调各提示一次，阵亡本身不响（「提示音：开 / 关」可关闭，设置会保存，打开时在对局中试播一声）。提示音由 League 主程序播放：组件读取标记后写入 `respawn-marks.json`，主程序按 2999 的复活倒计时播放；组件在游戏获得焦点时属于后台 UWP 应用，Windows 会静音其声音。数据来自 2999 的复活倒计时；2999 不提供视野或位置，所以不能提示英雄进出视野。标记只保存在本局，换局或该位置换英雄时清除。也不会自动发送聊天。预览检查：`GameBar/Verify-Preview.ps1 -DetailTab marks`。

召唤师技能计时（仅我方）：名单卡片右侧显示每位玩家的两个召唤师技能。2999 的 `summonerSpells.rawDisplayName`（如 `GeneratedTip_SummonerSpell_SummonerFlash_DisplayName`）给出技能内部名，名称、冷却和图标按客户端版本取自 Data Dragon 的 `summoner.json`，缓存在 `%LOCALAPPDATA%/League/Cache/ddragon-summoners/<版本>`（`SummonerSpellData`）；各模式使用自己的技能（大乱斗的雪球 80 秒、斗魂竞技场的专属技能），所以冷却跟着技能走。我方（含自己）的图标可点击：点一下按当前对局时间开始计时，图标变暗并倒数秒数，计时中再点取消；冷却 = 基础冷却 × 100 / (100 + 召唤师技能急速)，急速只算看得到的来源：明朗之靴 10、绯红明朗 20，以及自己的符文「星界洞悉」18（2999 只给自己的符文）；另加模式给所有人的急速：嚎哭深渊光环在大乱斗和海克斯大乱斗 +70（闪现 300 / 1.7 ≈ 176.5 秒），无限火力 +300，这两项由游戏脚本施加、数据里没有数值，取自英雄联盟维基（`SummonerSpells.ModeHaste`）。模式改写的基础冷却（大乱斗虚弱 290 秒、无限火力惩戒 10 秒）读自 CommunityDragon 的 `game/shared.cdtb.bin.json`（与英雄技能相同的模式字段），只保留改写值，按版本缓存为 `modes-r1.json`；读取失败时用 Data Dragon 的冷却，五分钟后重试。斗魂竞技场是否有地图急速未核实，海克斯大乱斗中改变召唤师技能冷却的海克斯未计入。计时写在组件的 `summoner-timers.json`（按对局区分），主程序读取后在快照中回传，组件重启后取回；计时结束时主程序响三声升调并写入日志（`SummonerTimerAlerts`），程序中途启动时已经结束的计时不响；控制保命页「召唤师提示音：开 / 关」写入 `control-settings.json` 的 `summonerSound`。右键我方技能图标发送该技能的计时（聊天请求 `kind: summoner`，带座位、英雄和技能位 `spell`），走与其他发送相同的确认流程（按 Win＋G 返回游戏、保持聊天输入框关闭后发送，可取消）；主程序按发送时的最新数据生成“召唤师技能：技能 还有 m:ss，约 m:ss 转好”或“已转好”（不写英雄名，由用户在 Tab 计分板点击头像标明），并再次确认该玩家是我方，未开始计时或数据超过 15 秒未更新时不发送（`SummonerChatMessage`）。敌方只显示图标，不可点击，快照也不带冷却和开始时间：Riot 的第三方规则禁止追踪敌方召唤师技能冷却（包括手动计时器）。回归检查 `--summoner-timer-checks`。

控制保命：底部「控制保命」按钮打开独立页面，按名单顺序列出敌方、我方每位英雄的关键控制技能和保命装备，不排序、不推荐集火目标。标题栏「发送控制 ▾」可选我方或敌方，把该阵营每个英雄的控制技能发到游戏聊天（聊天请求 `kind: controls`），如 `【控制·对方】拉克丝 Q禁锢 E减速 R…；…`，远程强减速记作「减速」，被回归基本功封印的大招不列出，还在读取的英雄写「读取中」，超过一条消息长度时按英雄分成多条（`OverlayControlChatMessage`）；走与其他发送相同的确认流程。控制技能来自客户端英雄资源（`/lol-game-data/assets/v1/champions/{id}.json`，与「技能」页共用缓存），按技能说明识别击飞、击退、压制、晕眩、魅惑、嘲讽、恐惧、沉睡、禁锢、变形、拉拽、沉默，不含致盲；排除移除 / 免疫控制、英雄自身变形或拉向目标、被动的触发条件等描述（`ChampionControlSkills`），说明没写到的效果可能遗漏。远程强减速（施法距离 ≥ 600、满级减速 ≥ 40%）以蓝色显示，或并入同一技能的控制标签：客户端资源不含减速数值，所以按客户端版本从 CommunityDragon 读取该英雄的游戏数据（`game/data/characters/{英雄}/{英雄}.bin.json`），取技能及其子技能名为 Slow 的数值（排除自身、攻速减速、抗性和系数），只保留客户端说明里写了「减速」的技能（`ChampionSlowSkills`）；技能等级数取自同一份数据的提示信息（大招多为 3 级，读不到时大招按 3 级、其他按 5 级），不会读到不存在的等级；列表按满级减速筛选，但显示的减速百分比和时长按该英雄当前等级可达到的最高技能等级计算（基础技能在 1/3/5/7/9 级各开放一级，大招在 6/11/16 级开放，四级大招从 1 级开始；实际加点未知，所以是当前最多能有的数值），等级来自 2999，读不到时按满级；减速时长优先用减速自己的时长，没有时取技能的通用控制时长，再没有才取区域持续时间，标签显示秒数（如「减速50% 2秒」），区域比减速持续更久时在提示里另外说明，数据里没有时长时只显示减速百分比；结果按客户端版本和识别规则版本缓存在 `%LOCALAPPDATA%/League/Cache/cdragon-spells`，每个英雄只存几十字节，读取失败时只显示硬控。近身减速暂不列入。保命装备取自 2999 的装备栏（与 Tab 计分板相同）：中娅沙漏、探索者的护臂、守护天使、水银饰带 / 弯刀、女妖面纱、夜之锋刃、翠绿屏障、斯特拉克、不朽盾弓、玛莫提乌斯之噬、海克斯饮魔刀、石像鬼石板甲（`SurvivalItems`）；2999 不提供装备冷却，已用过的也会显示。保命提示音（标题栏下拉，可分别勾选「敌方」「我方（含自己）」，默认只开敌方；勾选时不试听，避免和真实提示混淆）：所选阵营做出保命装备时，主程序播放该装备的游戏音效（`SurvivalItemAlerts`、`ItemSoundLibrary`），音效取自英雄联盟官方维基托管的游戏原声（Ogg Vorbis，用 NVorbis 解码为 WAV），首次使用时下载并缓存到 `%LOCALAPPDATA%/League/Cache/item-sounds`；维基没有的探索者的护臂、水银弯刀、翠绿屏障分别用中娅沙漏、水银饰带、女妖面纱的音效。2999 看不到装备冷却和使用，所以提示的是做出装备；首次看到某人时已有的装备不提示，卖掉再买会再提示；每次播放都记在主程序日志 `%LOCALAPPDATA%/League/Logs/tier-chat-<进程号>.log`（阵营、英雄、装备）。开关写在组件的 `control-settings.json`，回归检查 `--survival-sound-checks`。减速标签同时给出覆盖率（如「减速50% 2秒 覆盖15%」）：减速时长 ÷ 同一技能等级的冷却（充能技能用每层充能时间），冷却按该玩家的技能急速缩短——自己取 2999 的技能急速，其他玩家按装备说明里的技能急速加上已记录海克斯的急速估算，记录了纯粹主义者 - 术师时再把附加攻速（装备攻速 + 英雄等级成长攻速）按每 1% 换 0.65 急速加进去（`PlayerHaste`），未含符文、其他海克斯和模式加成；表示每次冷却好就命中时减速约占的时间，未计命中返还和区域内的再次减速（`SlowCoverage`）。每位玩家另有「生命」一行：自己取 2999 的实际生命、护甲、魔抗；其他玩家按 Data Dragon 英雄属性表（按客户端版本缓存在 `%LOCALAPPDATA%/League/Cache/ddragon-stats`）的等级成长、客户端装备说明里的生命 / 护甲 / 魔抗和已添加的坦克引擎层数估算，标「约」，看不到其他海克斯、属性碎片、叠层装备和模式道具，实际通常更高；自己的提示里同时给出同一公式的估算和实际差距，作为偏差参考。物理 / 法术有效生命 = 生命 × (1 + 抗性/100)，未计穿透。「海克斯」一行只读显示该玩家在「海克斯」页的记录。预览检查：`GameBar/Verify-Preview.ps1 -DetailTab controls`，回归检查 `--control-checks`、`--augment-stack-checks`、`--health-checks`。

兵线：底部「兵线」按钮显示下一波倒计时，点击打开独立的「兵线」页，「返回」回到名单或原英雄详情。出波、炮车、每波价值、超级兵和到达防御塔时间由主程序按模式规则和推塔事件计算（`MinionWaveForecaster`），快照 `waves` 字段携带游戏时间与对应的本机时间，组件只做本地倒计时；超过 5 秒未更新时暂停。到达时间为无人干扰时的估计。每路的进度条显示双方塔与最新一波兵的理论位置、预计相遇时间，以及按建筑损失推测的兵线大致位置。页面下方「现在阵亡需等待」按等级与游戏时间列出双方现在阵亡的复活时间。「发送 ▾ → 兵线（发到队伍）」可把出波与炮车、超级兵或阵亡代价发到队伍聊天，内容在返回游戏、输入前按最新数据生成。规则与数据来源见 [docs/minion-wave-requirements-draft.md](../docs/minion-wave-requirements-draft.md)，回归检查 `--minion-wave-checks`。

炮车波：下一波是炮车波时，底部兵线按钮变成金色并显示「兵线 炮车 0:23」，不打开兵线页也能看到。兵线页标题栏的「炮车提示音 ▾」可选「关」（默认）、「下一波是炮车时」（炮车波的前一波出兵时提示，约提前一波）或「炮车波出兵时」；提示音为两声低音，由主程序播放（游戏在前台时 Windows 会静音组件），选择时不试播。设置随 `control-settings.json` 的 `cannonSound`（off / next / spawn）传给主程序；主程序每次读到兵线预测时记住接下来的出兵时间，出兵时间在两次读取之间经过才提示，首次读取或两次读取相隔超过 5 秒（中途启动、重连）只记录不提示（`CannonWaveAlerts`），每次提示写入 `tier-chat` 日志。回归检查 `--minion-wave-checks`。

兵线小组件：同一组件包另注册了「League 兵线」（扩展 Id `Waves`），按 Win＋G 从小组件列表打开，点图钉后可单独悬浮在游戏上方，与「League 对局速览」互不影响；它不响应主程序的自动显示 / 隐藏命令。第一行显示下一波倒计时、普通波或炮车波、波次，以及之后的炮车倒计时（有水晶被摧毁时改为列出出超级兵的路）；右侧是自己的阵亡时间：存活时灰色「阵亡 32 秒」为现在阵亡需等待的复活时间（按等级与游戏时间推算，悬浮可看送死建议），阵亡时变为红色「复活 12」实时倒计时；模式没有复活时间表时不显示。右侧 ▴ / ▾ 收起为一行或展开各路：每路一条水晶到水晶的进度条，显示双方建筑、正在行进的兵和 ◆ 默认交汇点（双方前塔中点），右侧是我方下一波到达交汇点的时间。收起状态存在组件本地设置；切换时组件按路数请求调整窗口高度，宽度保持玩家拖动后的值。背景不透明度在主程序「设置 → 对局速览」的「兵线组件不透明度」中调整（20%–100%，默认 85%，仅在选择 Game Bar 时显示），随快照的 `waveWidget.opacity` 下发，与 Game Bar 自带的组件透明度相乘；只淡化背景，文字和图标保持不透明。鼠标穿透开启时需通过 Win＋G 操作收起按钮。对局中主程序支持语音时，底部多一行简易语音：左键「识别」开始录音，说完点「停止」，识别结果只显示不能编辑（悬浮看全文），状态只显示「准备中」「请说话」「识别中」「回游戏发送」「已发送」「未发送」等简短文字，完整原因悬浮查看；有结果后左键变为「重新识别」；右键「发送」把识别结果作为一条普通聊天发到当前频道，等待期间变为「取消」。发送前同样需要在 20 秒内回到游戏并保持聊天框关闭，送达后清空，未送达时显示原因并保留文字可再次发送；识别完成不会自动发送。它与速览组件的语音输入共用主程序的同一条录音和发送通道，同一时间只能有一个录音或发送；固定状态下（Win＋G 已关闭）也可操作。日志只记录开始、完成和发送结果，不记录识别文字。截图检查：放好详情样例后运行 `GameBar/Verify-Preview.ps1 -WaveMini expanded`（或 `collapsed`），输出 `wave-mini-preview-*.png`。实际全屏下的透明与悬浮效果需进游戏确认。

阵容：大乱斗和海克斯大乱斗中，底部「阵容」按钮打开独立页面，并排列出我方和敌方的阵容分析，与选人助手的阵容分析使用同一个 arammeta 统计模型（`AramTeamScore`、`AramCapabilityGrades`）：前排、控制、开团、伤害、消耗、清线、续航七项能力的条形和等级（按同人数随机阵容排名，D 为低于短板阈值，标红），物理伤害占比和前排人数，短板汇总，缺少统计的英雄；海克斯大乱斗另有估计胜率（英雄、搭配、阵容三部分和可信度）和提升最大的三组队友搭配，普通大乱斗不显示估计胜率。对局中已不能换人，所以不给换人建议。主程序在名单变化后计算一次（统计读取失败时一分钟后重试，`GameBarComposition`），快照字段 `composition`，其他模式没有这个字段，按钮也不显示。标题栏「发送阵容 ▾」可把我方或敌方的能力等级、物理占比和前排人数发到游戏聊天（聊天请求 `kind: composition`），走与其他发送相同的确认流程。回归检查 `--gamebar-composition-checks`。

海克斯：底部「海克斯」按钮打开独立页面，是记录海克斯的唯一入口（2999 不提供海克斯）。按名单顺序列出每位玩家，「＋ 海克斯」菜单按主程序下发的目录（`AugmentCatalog`，快照 `augmentCatalog`）列出所有影响生命、抗性或冷却的海克斯：无限循环往复 / 缩小引擎 / 坦克引擎自动计层（参与击杀和死亡从本局击杀事件推算，需要对局时间；− / + 修正即新的起点）；吞噬灵魂、保持坚定（记已获得的抗性总量）、急速之追求（记已完成的档）手动记层；循环往复、回归基本功、大招工具人、终极唤醒、纯粹主义者 - 术师、面包系列、星界躯体、歌利亚巨人、亮出你的剑、玻璃大炮、科学狂人为固定加成。需要选择的（科学狂人的形态、急速之追求的技能、吞噬灵魂是否第一个海克斯、保持坚定的抗性）点「⇄」切换。每位玩家另有手动「大招急速」（符文等来源）。记录写在组件的 `augment-stacks.json` 与 `ultimate-haste.json`，按对局区分、换局清空，组件重启后从快照取回。主程序汇总每位玩家的记录（`AugmentEffects`）：生命百分比按客户端数据的 HealthAmp 解读为最大生命的提升、逐项相乘，固定生命先加，玻璃大炮最后按 70% 封顶；亮出你的剑的生命加成按英雄默认攻击距离（Data Dragon）从 500 起每 15 距离提高 10%，650 时翻倍；保持坚定可选护甲 / 魔抗及是否第一个海克斯（非第一个另加 20 护甲和魔抗）；回归基本功封印大招，冷却页和本局页显示「已封印」，控制保命页不再列出该英雄的大招控制和减速；技能急速加到其他玩家的估算里；冷却规则用于「本局」页技能冷却、控制保命页减速覆盖率和「冷却」页。条件或临时效果（电涌力场、最终形态等）和依赖读不到属性的换算（尤里卡、由暴生急、由心及物）不在目录中。预览检查：`GameBar/Verify-Preview.ps1 -DetailTab augmentpage`，回归检查 `--augment-stack-checks`、`--cooldown-option-checks`、`--health-checks`。

冷却计算：英雄详情的「冷却」页（任意英雄，有技能数据时显示）列出 Q / W / E / R 的冷却。起点由主程序给出：自己的技能等级取 2999，其他玩家按当前等级可达的最高等级（实际加点未知）；技能急速同控制保命页（自己的取 2999，其他玩家为估算）。可以逐个调整技能等级、用 −10 / −1 / +1 / +10 调整急速，页面立即重算；技能等级和急速只是本页的假设，「恢复」回到主程序给出的数值，换英雄或换局后重置。「海克斯」一行只读列出该玩家已记录、影响冷却的海克斯和大招急速，按各自规则计入（面包系列、急速之追求只加对应技能，纯粹主义者 - 术师再乘 0.9，大招工具人按 Wiki：技能急速只作用于大招并 +100，大招冷却按 (技能急速 + 大招急速) × 1.5，自己的 2999 急速已含这 100，其他玩家的估算自动加上），旁边的按钮打开「海克斯」页修改。冷却 = 基础冷却 × 100 / (100 + 急速)，充能技能算每层充能时间；命中返还未计入。预览检查：`GameBar/Verify-Preview.ps1 -DetailTab cooldowns`，回归检查 `--cooldown-checks`。
